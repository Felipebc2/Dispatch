# CyberChef: Context for Claude

Quick reference. CyberChef is a **web/manual** tool, so Claude does not control it via MCP/API; the
role here is to **identify the encoding/cipher and replicate the logic via terminal/script** when
that's faster than the UI, or to **advise which recipe to build** in the UI when the chain is
long/visual.

## When Claude should solve it directly (without opening CyberChef)

A single, obvious layer, where solving it via the shell is faster than describing the recipe:

```bash
# Base64
echo "<data>" | base64 -d

# Hex
echo "<data>" | xxd -r -p
# or
python3 -c "print(bytes.fromhex('<data>'))"

# URL-encode
python3 -c "import urllib.parse; print(urllib.parse.unquote('<data>'))"

# ROT13
echo "<data>" | tr 'A-Za-z' 'N-ZA-Mn-za-m'
```

## When to advise using CyberChef (UI) instead of scripting

- A chain of **3+ stacked encodings** and the user wants to see each intermediate step: faster to
  build visually than to have Claude write/run a script per layer.
- **Magic wand** is more efficient than Claude guessing by inspection when the encoding isn't
  obvious up front: suggest "throw it at CyberChef's Magic" before spending rounds guessing.
- The user already has the tab open and prefers a visual workflow, so don't insist on the terminal
  as a tool default.

## When Claude should write a Python script instead of either option

- **XOR brute-force with a large keyspace** (more than a few thousand combinations) or you need a
  scoring heuristic (character frequency, dictionary) to find the right plaintext:
  `pycryptodome`/a Python loop is faster and you can process the result programmatically.
- **Repeating the same recipe across many inputs** (a batch of hashes/strings): CyberChef
  processes one input at a time in the UI; a script iterates the whole list.
- **AES/DES with a known key but parameters that need trial and error** (CBC vs. ECB mode,
  padding, null vs. random IV): faster to test variations in `pycryptodome` than to reconfigure
  the operation in the UI over and over.

## Quick encoding identification (visual heuristic)

| Observed pattern | Likely encoding |
|---|---|
| Ends in `=` or `==`, alphabet A-Za-z0-9+/ | Base64 |
| Only `0-9a-f`, even length | Hex |
| Contains `%XX` | URL-encode |
| Alphabet A-Z2-7, no lowercase | Base32 |
| Multiple of 32/40/64 hex chars | Hash (MD5=32, SHA1=40, SHA256=64); doesn't decode, see the Hash Cracking manual |
| JSON-like after decode: `{"alg":...}` | JWT (see the JWT manual) |
| All text turns "unintelligible" but with a normal letter-frequency pattern | Substitution cipher (Caesar/Vigenère) |

## Reference: CyberChef operation names (to guide the user in the UI)

`From Base64` · `From Hex` · `URL Decode` · `From Base32` · `XOR` · `XOR Brute Force` ·
`ROT13` · `Vigenère Decode` · `Magic` · `AES Decrypt` · `DES Decrypt` · `JWT Decode` ·
`Extract IP addresses` · `Extract URLs` · `Gunzip` · `Raw Inflate` · `Detect File Type`

## Limitations

- Doesn't crack hashes/passwords (no wordlist/credential brute-force); that's `Hash-Cracking` or
  local `hashcat`/`john`.
- Not a substitute for broken RSA or asymmetric crypto; use `RsaCtfTool` or dedicated scripts.
- Runs in the browser: **don't send real sensitive data** through unofficial third-party CyberChef
  deployments floating around out there. Always use the official GCHQ link.
