# Web Check: Fundamentals and When to Use It

Introductory manual for Web Check, an all-in-one passive recon report for a website. Practical
walkthrough in `2. Guia Passo a Passo.md`; competition reference in `3. Contexto para Claude.md`.

Web Check is an open-source project by **Alicia Sykes** ([@Lissy93](https://github.com/lissy93)),
MIT-licensed: https://github.com/lissy93/web-check. Public instance: https://web-check.xyz/.

## What it is

You give Web Check a URL and it runs 30+ checks in parallel, then shows them as cards and lets you
export everything as one JSON file (`web-check-results.json`). The checks most useful in a CTF:

| Report key | What it tells you |
|---|---|
| `dns`, `txt-records` | A/AAAA/MX/NS/TXT/CNAME/SOA records; TXT is a classic flag hiding spot |
| `robots-txt`, `sitemap` | Disallowed and listed paths: hidden routes |
| `linked-pages` | Internal and external links found on the page |
| `headers`, `cookies` | Server banner, custom `X-` headers, cookie names and flags |
| `redirects` | The redirect chain the URL goes through |
| `ssl` | Certificate issuer, dates and `subjectaltname` (other hostnames) |
| `security-txt` | Contact and policy file, sometimes with hints |
| `ports`, `server-info` | Open common ports, IP, ASN, hosting |
| `tech-stack` | Frameworks, CMS and libraries detected |
| `whois`, `subdomains`, `archives` | Registration, known subdomains, Wayback history |

## When it is worth using

- **First look at a public web target or domain** (WEB or OSINT): one page replaces 8 to 10 manual
  commands (`dig`, `curl -I`, robots, sitemap, crt.sh...).
- OSINT on a company/site: hosting, registrar, mail setup, linked social profiles.
- When the user already ran it and hands over the exported JSON.

## When it is NOT worth it

- **Private or VPN targets** (`10.x`, `192.168.x`, `.local`): the public instance can't reach them.
  Use `curl`/`dig`/`ffuf` directly (`generic-recon-scanner`).
- **Offline competitions**: the public instance needs internet. Self-hosting is possible
  (`docker run -p 3000:3000 lissy93/web-check`, then `localhost:3000/api/<check>?url=<target>`), but
  13 checks (whois, subdomains, archives, threats...) are skipped for private hosts anyway.
- It finds no vulnerability by itself: it is triage. Exploitation goes to the matching Arsenal entry.
