# RsaCtfTool — Step-by-Step Guide

Workflow for attacking weak RSA in a CTF challenge. Concepts in `1. Fundamentos e Quando Usar.md`.

## 0. Install

```bash
# Arch — deps compiled via pacman; only factordb-pycli is pip-only (lives in ~/ctf-venv):
sudo pacman -S --needed python-gmpy2 python-pycryptodome python-cryptography \
    python-requests python-urllib3 python-tqdm python-psutil python-z3-solver
```
On this host the repo is already cloned at `~/tools/RsaCtfTool` and installed (editable) in
`~/ctf-venv` (`--system-site-packages`, which sees the system's gmpy2/pycryptodome/z3 +
factordb-pycli). The new repo is a `src/` package with a console-script — invocation:
```bash
~/ctf-venv/bin/RsaCtfTool --publickey key.pem --private      # or: source ~/ctf-venv/bin/activate && RsaCtfTool ...
# (setup, already done: cd ~/tools/RsaCtfTool && ~/ctf-venv/bin/pip install -e .)
```

## 1. Inspect what you have

```bash
openssl rsa -pubin -text -in key.pem -noout     # see n (modulus) and e (exponent) of the public key
```
Note the size of `n` (bits) and the value of `e` — this already points to the likely attack:

| Signal in the parameters | Likely attack |
|---|---|
| Small `n` (< ~512 bits) | factorization (FactorDB/trial) |
| `e` = 3 (or very small) + ciphertext | low-exponent root attack |
| Huge `e` (close to `n`) | Wiener / Boneh-Durfee (small `d`) |
| Same `n`, two different `e` | common modulus |
| Same `m`, several `n`, small `e` | Håstad broadcast |
| `p` and `q` close | Fermat |

## 2. Run with a key file

```bash
# recover the private key from the public one
python3 RsaCtfTool.py --publickey key.pem --private

# decrypt a ciphertext directly
python3 RsaCtfTool.py --publickey key.pem --decrypt cipher.bin
python3 RsaCtfTool.py --publickey key.pem --decryptfile cipher.txt
```

## 3. Run with loose n/e (no .pem)

```bash
python3 RsaCtfTool.py -n <N> -e <E> --private
python3 RsaCtfTool.py -n <N> -e <E> --uncipher <C>
```

## 4. Target a specific attack (faster than the whole sweep)

```bash
python3 RsaCtfTool.py --publickey key.pem --private --attack wiener
python3 RsaCtfTool.py --publickey key.pem --private --attack fermat
python3 RsaCtfTool.py --publickey key.pem --uncipher C --attack boneh_durfee
# list available attacks:
python3 RsaCtfTool.py --list-attacks
```

## 5. Multi-key cases

```bash
# common modulus (same n, two e, two ciphertexts)
python3 RsaCtfTool.py -n <N> -e <E1> --uncipher <C1> -e2 <E2> --uncipher2 <C2> --attack common_modulus

# Håstad (several public keys + several ciphertexts)
python3 RsaCtfTool.py --publickey "key*.pem" --uncipherfile "c*.bin" --attack hastads
```

## 6. If the tool doesn't solve it: manual decrypt from p,q

When you managed to factor (via FactorDB or another attack) but still need to build the decrypt:
```python
from Crypto.Util.number import inverse, long_to_bytes
d = inverse(e, (p-1)*(q-1))
m = pow(c, d, n)
print(long_to_bytes(m))
```
