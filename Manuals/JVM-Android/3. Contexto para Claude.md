# JVM-Android: Context for Claude

Quick competition reference for Java bytecode and Android apps. The role here is to pick the right
layer (JAR, APK, native `.so`), decompile, and locate the check that is usually hidden off the
visible path.

## Decision flow

```
What is the artifact?
 ├─ .jar / .class → cfr or procyon for source; javap -c -p when the decompiler output is wrong
 ├─ .apk / classes.dex → jadx for Java; apktool d for smali + resources + manifest
 └─ logic seems missing from the Java?
     ├─ class built at runtime (ClassLoader.defineClass) → rebuild the byte[], expect CAFEBABE
     ├─ native method (System.loadLibrary) → reverse lib/<abi>/*.so in Ghidra (JNIEnv*, jobject)
     └─ heavy obfuscation (ProGuard/R8) → hook at runtime with Frida/jdb instead of reading
```

## Quick-reference commands

```bash
javap -c -p -s Klass.class                 # raw bytecode, private members, signatures
cfr app.jar --outputdir src                # decompile a JAR to Java (or: procyon -o src app.jar)
jadx -d out app.apk                        # APK/DEX to Java in one step
apktool d app.apk -o out_at                # smali + decoded resources + AndroidManifest.xml
unzip app.apk classes.dex -d . && d2j-dex2jar classes.dex -o app.jar   # DEX -> JAR for cfr
nm -D --defined-only lib/arm64-v8a/libx.so | grep Java_   # statically named JNI methods
```

```js
// Frida: observe or override a Java method
Java.perform(() => { const C = Java.use('com.pkg.Checker');
  C.verify.implementation = function (x) { const r = this.verify(x); console.log(x, r); return r; }; });
```

## Common failure modes (and the cause)

| Symptom | Likely cause |
|---|---|
| Decompiled code will not recompile | synthetic/obfuscated members; trust `javap -c` bytecode |
| A method body is just `native` | logic is in `lib/<abi>/*.so`; reverse the `.so` |
| JNI function name not found | registered dynamically via `RegisterNatives` in `JNI_OnLoad`, not statically named |
| `.so` will not load/run on host | it is ARM only; use an emulator/Frida on-device, or Unicorn for the pure math |
| Rebuilt class bytes look corrupt | Java `byte` is signed; mask `& 0xff`, and the payload may be gzip/DEX |
| Nothing interesting in the app | it is a thin client over a web API; the logic is server-side |

## When to flag that this is not the vector

- The APK only talks to a backend and ships no check: treat it as a WEB/API target.
- A standalone native ELF with no JVM: that is plain Ghidra REV, not this manual.
