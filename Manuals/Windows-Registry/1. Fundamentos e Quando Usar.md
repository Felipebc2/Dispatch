# Windows-Registry: Fundamentals and When to Use It

Introductory manual for offline Windows registry hive forensics. Walkthrough in
`2. Guia Passo a Passo.md`; competition reference in `3. Contexto para Claude.md`.

## What it is

The Windows registry is a set of binary hive files (format `regf`). In forensics challenges you get
the raw hives from a disk image and parse them offline to answer questions about what ran, what was
installed, and what persisted.

The hives and what they hold:
- **SYSTEM**: services, the current ControlSet, ShimCache (AppCompatCache), BAM/DAM.
- **SOFTWARE**: installed programs, Run/RunOnce autostart, network profiles.
- **SAM**: local user accounts and password hashes.
- **NTUSER.DAT** (per user): UserAssist, RecentDocs, TypedPaths, ShellBags.
- **Amcache.hve**: a separate hive with rich program-execution evidence (SHA1, paths).

The kit:
- `regipy` (Python): `registry-transaction-logs` to replay logs, `regipy-dump`, and plugins.
- RegRipper (`rip.pl`): plugin-driven text reports.
- Eric Zimmerman tools: AppCompatCacheParser, Registry Explorer (GUI), AmcacheParser.
- `python-registry` for a dependency-light custom parser.

## When it is the right tool

- The artifact is a hive file (`SYSTEM`, `SOFTWARE`, `NTUSER.DAT`, `SAM`, `Amcache.hve`) or a disk
  image you have mounted and pulled hives from.
- A question asks "what program ran", "what was installed", "what persisted", or wants a timestamp
  tied to a binary.

## When it is NOT

- The evidence is in event logs (`.evtx`): that is a different parser (for example Chainsaw, evtx).
- The data is in a memory dump: that is Volatility, not hive parsing.
- You only need a file from the filesystem: carve it from the image instead.
