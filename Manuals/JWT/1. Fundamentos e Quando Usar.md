# JWT — Fundamentals and When to Use It

Introductory manual on JSON Web Tokens: structure, where jwt.io fits in, and what the common
attack vectors are in CTF. Practical walkthrough in `2. Guia Passo a Passo.md`.

## What a JWT is

JSON Web Token: a compact format for transmitting signed (and optionally encrypted) information
between parties, widely used for authentication/sessions in web APIs.

Structure: three parts separated by a dot, each in **Base64URL**:

```
header.payload.signature
eyJhbGciOiJIUzI1NiJ9.eyJ1c2VyIjoiYWRtaW4ifQ.dGhpc19pc19hX3NpZ25hdHVyZQ
```

- **Header:** the signing algorithm (`alg`) and type (`typ`). E.g. `{"alg":"HS256","typ":"JWT"}`
- **Payload:** the claims (data) — e.g. `{"user":"admin","exp":1234567890}`. **It's not encrypted,
  only encoded** — anyone can decode and read it.
- **Signature:** guarantees integrity. Computed over `header.payload` using the header's algorithm
  + a secret (HMAC) or a private key (RSA/ECDSA).

## What jwt.io is

https://jwt.io is a visual JWT decoder/encoder: paste the token and it shows the decoded header and
payload side by side, and lets you edit and re-sign **if you know the secret**. It doesn't crack
secrets or run attacks — it's just visualization/manual editing.

> **Security note:** jwt.io runs in the browser and, by default, doesn't send the token to their
> server — but in CTF, prefer pasting test/challenge tokens, never real production credentials into
> any third-party tool.

## Common attack vectors in CTF

1. **`alg: none`** — some poorly implemented servers accept a token with no signature. Edit the
   header to `{"alg":"none"}`, remove the signature, and send `header.payload.` (with an empty
   trailing dot).
2. **Algorithm confusion (RS256 → HS256)** — if the server uses RSA (public/private key) but
   doesn't validate the algorithm declared in the header, an attacker who knows the **public key**
   can sign an HS256 token using the public key as the HMAC secret.
3. **Weak secret (HS256 brute-force)** — if the algorithm is HMAC and the secret is
   short/dictionary, it can be cracked offline with `hashcat` or `jwt_tool`.
4. **`kid` (Key ID) injection** — the header can point to which key to use (`kid`); if the server
   doesn't sanitize that field, you can point it at a file/path controlled by the attacker (path
   traversal, SQLi in the lookup, or even a predictable fixed value).
5. **`jwk`/`jku` injection** — variants where the token itself carries or points to the public key
   to use for validation; if the server trusts it blindly, the attacker embeds their own key and
   signs with the corresponding private key.
6. **Manipulable claims** — after defeating the signature (or finding `none`/a weak secret), edit
   claims like `role`, `admin`, `user` to escalate privileges.

## When jwt.io is worth using

- **Quick inspection:** decode header/payload to understand the algorithm and claims before
  deciding on the attack.
- **One-off manual editing:** you already know the secret (or it's `none`) and want to edit claims
  and regenerate quickly, visually.

## When it's NOT worth it (use another tool)

- **Secret brute-force** — jwt.io doesn't do it; use `hashcat -m 16500` or `jwt_tool`.
- **Automating multiple attacks (alg confusion, kid, jwk)** — `jwt_tool` (Python) has these modes
  ready to go, much faster than editing by hand.
- **Scripting/repetition** (generating several test tokens) — use `pyjwt` directly in Python.

## jwt.io alone vs. Claude/scripts

| Situation | Best approach |
|---|---|
| Just decode and read claims | jwt.io — faster visually |
| `alg:none` or already-known secret, edit a claim and re-sign | jwt.io manually, or `pyjwt` if repeating |
| Unknown secret, needs brute-force | `hashcat`/`jwt_tool` — jwt.io doesn't help here |
| RS256→HS256 algorithm confusion | `jwt_tool` has an automated mode; by hand is slower |
| You don't know which vector to try | Ask Claude to analyze the header+payload and suggest the most likely vector |
