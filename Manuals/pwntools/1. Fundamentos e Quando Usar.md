# pwntools — Fundamentals and When to Use It

Introductory manual for `pwntools`, the Python Swiss Army knife for exploiting binaries/services.
Practical walkthrough in `2. Guia Passo a Passo.md`; competition reference in
`3. Contexto para Claude.md`.

## What it is

`pwntools` (https://github.com/Gallopsled/pwntools) is a Python library for writing CTF exploits
fast. It standardizes the tedious tasks: connecting to a local or remote process, packing integers
into little-endian bytes, building ROP chains, parsing ELF/libc, resolving symbols, finding
gadgets, and switching between local testing and the remote target by changing a single line.

```python
from pwn import *          # imports everything (context, remote, process, ELF, ROP, p64, cyclic...)
```

## Key concept: `context`

Almost everything depends on the global `context` — architecture, bits, and endianness. Setting it
wrong makes `p64`/shellcode/ROP come out wrong with no explicit error:
```python
context.binary = ELF("./chall")   # sets arch/bits/endian automatically from the ELF
# or manually:
context.arch = "amd64"            # "i386" for 32-bit
context.log_level = "debug"       # shows every byte sent/received (great for debugging)
```

## Local vs. remote (the 1-line swap)

```python
io = process("./chall")           # local testing, with the system libc/LD_PRELOAD
io = remote("host.ctf", 1337)     # the competition's remote target
```
Exploit pattern: develop 100% locally until it works, then swap `process` for `remote`.
The target's libc almost always differs from the local one — see the gotcha in the guide.

## When it's worth using

- **PWN** (always): stack overflow, format string, ROP, heap, shellcode — it's the base tool.
- **NET / a custom socket service:** automate interaction with a service that asks for many rounds,
  a proof-of-work, or a menu — `remote` + `recvuntil`/`sendline` is cleaner than `nc`.
- **Any challenge with a proof-of-work** before it unlocks: solve the PoW in a loop and send it.

## When it's NOT worth it

- A **pure web** challenge (HTTP) — use `requests`/Burp; pwntools isn't for that.
- A simple **single-round** interaction with `nc` — pasting by hand is faster than writing a script.
- **Offline crypto/REV** — pwntools doesn't help break a cipher or decompile (that's
  Ghidra/sage/z3); it only comes in if there's a remote service to interact with at the end.

## Tools that go with it

- **Ghidra** (`Manuals/Ghidra/`) — find the vulnerable buffer, the offset, the `win` function,
  gadgets.
- **`checksec`** (ships with pwntools) — see canary/NX/PIE/RELRO before choosing the technique.
- **`one_gadget`** — find a single address in libc that already gives a shell (useful in a tight
  ret2libc).
- **`pwninit`** — download/patch the challenge's correct libc automatically.
