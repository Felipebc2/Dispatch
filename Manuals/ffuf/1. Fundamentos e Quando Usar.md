# ffuf: Fundamentals and When to Use It

Introductory manual for `ffuf` (Fuzz Faster U Fool), a fast web fuzzer written in Go. Practical
walkthrough in `2. Guia Passo a Passo.md`; competition reference in `3. Contexto para Claude.md`.

## What it is

`ffuf` (https://github.com/ffuf/ffuf) replaces one word in an HTTP request with each line of a
wordlist and reports the responses. The word it replaces is the keyword `FUZZ`: you put `FUZZ`
wherever you want the brute force to happen (in the URL path, a query parameter, a header, or the
POST body), point `-w` at a wordlist, and `ffuf` fires one request per entry.

```bash
ffuf -w wordlist.txt -u http://host/FUZZ
```

Because it is a single generic primitive (replace `FUZZ`, send, filter the response), the same tool
covers directory brute force, virtual-host discovery, parameter mining, and value guessing. The
skill is knowing where to place `FUZZ` and how to filter the noise.

## Key concept: filter and match the responses

A fuzz run returns thousands of responses; the signal is the handful that differ from the rest.
`ffuf` lets you drop responses you do not care about (filters) or keep only responses you do
(matchers), by status code, size, word count, or line count:

- `-mc` match status codes (default `200,204,301,302,307,401,403,405,500`), `-fc` filter them out.
- `-fs` / `-ms` by response size in bytes, `-fw` / `-mw` by word count, `-fl` / `-ml` by line count.
- `-ac` auto-calibration: ffuf sends a few random probes first, learns what a "not found" looks
  like on this target, and filters those automatically. Essential against soft-404 pages.

## When it is worth using

- **WEB**: the first enumeration step on almost any HTTP target: hidden directories and files,
  backup files, admin panels, API routes.
- Discovering **virtual hosts / subdomains** served off one IP by fuzzing the `Host` header.
- **Parameter mining**: finding an undocumented GET or POST parameter that changes behavior.
- Guessing **values** (a PIN, an id, a coupon) when the parameter name is known but the value is not.

## When it is NOT worth it

- The vector is already known (a visible SQLi, a JWT, an LFI): fuzzing paths wastes contest time.
- You only need to crawl linked content: a crawler (or just reading the HTML) beats brute force.
- A tiny, fully mapped app with three pages: just read them.

## When ffuf beats gobuster / dirsearch

- You need to fuzz something other than the path (header, body, parameter): `gobuster dir` only
  does paths; ffuf puts `FUZZ` anywhere.
- You need rich filtering (`-fs`/`-fw`/`-ac`) to beat a soft-404 that returns `200` for everything.
- You want to read a raw request saved from Burp with `-request` and just drop `FUZZ` into it.
- `gobuster` is still a fine, simple choice for a plain directory sweep; reach for ffuf when the
  run needs flexibility.

## Tools that go with it

- **SecLists** (`/usr/share/seclists/`): the wordlists most runs use (see file 2).
- **Burp / a proxy**: capture a real request, save it, feed it to ffuf with `-request`.
- **gobuster / dirsearch**: alternatives for the plain directory-sweep case.
