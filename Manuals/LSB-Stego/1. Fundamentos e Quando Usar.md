# LSB Steganography — Fundamentals and When to Use It

Manual on least-significant-bit (LSB — Least Significant Bit) steganography in images, focused on
the standalone `steglsb.py` script (brought in from a prior CTF toolkit, see `Arsenal/CRYPTO/`).
Practical walkthrough in `2. Guia Passo a Passo.md`.

## What it is

**LSB steganography** hides data inside an image by manipulating the least significant bits of
each pixel/color channel — changes imperceptible to the naked eye, but recoverable
programmatically if you know how many bits were used.

The `steglsb.py` script (Python, depends on `Pillow`) implements two operations:
- **Encode:** embeds a whole secret image inside a cover image, using the N least significant bits
  of each channel.
- **Decode:** extracts the hidden content from a target image, assuming N bits.

Unlike tools such as `steghide`/`zsteg` (which embed arbitrary data — text, a file — with an
optional password), `steglsb.py` is specifically **image-inside-image**, with no password.

## When it's worth using

- The challenge already indicates or suggests the steganography is **classic LSB** (the challenge
  name, or other tools like `zsteg`/`stegsolve` already showed activity in the low bits of some
  channel).
- You suspect the hidden "secret" image is **itself an image** (not text/a generic binary file) —
  in that case `steglsb.py -d` is more direct than trying to extract raw bytes.
- You already tried `steghide`/`zsteg`/`binwalk` and nothing matched, but the image has
  pure-LSB characteristics (a file size large for its dimensions, no visible lossy compression).

## When it's NOT worth it

- The image is a **JPEG** — LSB is destroyed by lossy compression; this method only works
  reliably on lossless formats (PNG, BMP). Confirm the format before trying.
- There's no indication of LSB steganography specifically — run
  `zsteg`/`steghide`/`exiftool`/`binwalk`/`strings` first (they're more generic and cover more
  techniques) before assuming it's image-inside-image.
- You don't know the number of bits (`bits`) used in the encode — decoding with the wrong `bits`
  produces noise, not an error; you have to test a small range (1-8) systematically.

## LSB vs. other image stego tools

| Situation | Best approach |
|---|---|
| You don't know which technique was used | `binwalk`/`exiftool`/`strings`/`zsteg` first (broad recon) |
| Suspect hidden text/file with a possible password | `steghide extract` |
| Suspect an image hidden inside an image (PNG/BMP) | `steglsb.py -d` (this manual) |
| Already ran all of the above and nothing matched | Reconsider the vector — it may not be image stego |
