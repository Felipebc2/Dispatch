# CrackStation / Hashes.com: Context for Claude

Quick reference. Online lookup (CrackStation/Hashes.com) is **manual/web**: Claude doesn't query
it via API; the role here is to **identify the hash and decide the right route** (lookup vs. local
`hashcat`), and to run `hashcat` via the terminal when applicable.

## Decision flow

```
1. Identify the type by length/format (see table below) or name-that-hash
2. Guide the user's manual lookup: CrackStation (https://crackstation.net) and/or
   Hashes.com (https://hashes.com/en/decrypt/hash); they have no free public API for
   automation, so it's really paste-into-the-web
3. If the user confirms "not found": go straight to local hashcat (don't wait on Hashes.com's
   paid cracking service, too slow for a timed competition)
4. Does the hash have a visible salt (format hash:salt, or the prompt mentions a salt)? Skip the
   online lookup entirely; it's no good for a unique salt, go straight to hashcat with a salted mode
```

## Identification table by length

| Length (hex) | Algorithm | Common hashcat mode |
|---|---|---|
| 32 | MD5 | `-m 0` |
| 32 (Windows/SAM context) | NTLM | `-m 1000` |
| 40 | SHA1 | `-m 100` |
| 56 | SHA224 | `-m 1300` |
| 64 | SHA256 | `-m 1400` |
| 96 | SHA384 | `-m 10800` |
| 128 | SHA512 | `-m 1700` |
| `$1$...` | MD5 crypt (Unix) | `-m 500` |
| `$2a$`/`$2b$...` | bcrypt | `-m 3200` |
| `$6$...` | SHA512 crypt (Unix) | `-m 1800` |

## Quick-reference commands (hashcat)

```bash
# Confirm the type when ambiguous
name-that-hash -t "<hash>"

# Basic crack with rockyou
hashcat -a 0 -m <mode> hash.txt /usr/share/wordlists/rockyou.txt

# With rules (common mutations) if the plain dictionary fails
hashcat -a 0 -m <mode> hash.txt rockyou.txt -r /usr/share/hashcat/rules/best64.rule

# Salted (file in hash:salt format)
hashcat -a 0 -m <salted_mode> hash.txt rockyou.txt

# View what's already been cracked (doesn't reprocess)
hashcat -m <mode> hash.txt --show

# Mask attack (password of known length/pattern, e.g. 4 digits)
hashcat -a 3 -m <mode> hash.txt ?d?d?d?d
```

## When NOT to spend time on lookup/cracking

- A hash of **evident high entropy** (looks randomly generated, not text): the challenge's vector
  is probably not "guess the original password", it's something else (e.g. an insecure comparison
  like `==` instead of `hash_equals`, hash reuse at a different endpoint, or length extension in
  MD5/SHA1, so check whether the challenge is about a **length extension attack** rather than
  cracking).
- The hash isn't of a password (it's a checksum/HMAC of content), so a lookup doesn't apply.
- You already tried `rockyou.txt` + basic rules and got nothing. Flag to the user that this may
  not be the right vector, instead of pushing on with larger wordlists (it costs competition time).

## Related tools (outside the lookup/hashcat scope)

- **`john` (John the Ripper):** an alternative to hashcat, better for specific formats
  (`/etc/shadow`, password-protected zip/rar via `zip2john`/`rar2john`).
- **`hash-identifier` / `name-that-hash`:** automatic type identification when the length alone is
  ambiguous.
