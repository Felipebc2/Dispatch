# CrackStation / Hashes.com — Fundamentals and When to Use Them

Introductory manual on hash-lookup databases (CrackStation and Hashes.com) and when to use each
vs. local cracking. Practical walkthrough in `2. Guia Passo a Passo.md`.

## What they are

**CrackStation** (https://crackstation.net) and **Hashes.com** (https://hashes.com) are web
services that maintain giant databases of `hash → plaintext` pairs precomputed from known
wordlists (rockyou, dictionaries, public leaks). You paste the hash, they query the database —
**it's not real-time brute-force**, it's a lookup.

- **CrackStation:** free, no signup, a database of ~15 billion entries. Supports MD5, SHA1,
  SHA256, SHA512, NTLM, LM, and others.
- **Hashes.com:** free for simple lookups; also has a paid "cracking as a service" offering (you
  submit hashes that weren't found and their community/service tries to crack them) and a built-in
  hash-type identifier.

## Key concept: why it sometimes does NOT find it

These services only find the plaintext if it's **already in the wordlist used to build their
database**. A strong/random password hash, or a **salted** hash (a unique salt per password, e.g.
`sha256(password + random_salt)`), will never match — the database has no entry for that specific
salt. In that case the path is local `hashcat`/`john` with a wordlist + rules, or exploiting
another vulnerability (the hash may not be the right vector).

## When it's worth using (online lookup)

- **The first attempt on any unknown hash** — it's free and instant, always worth trying before
  moving to local cracking.
- **Web/forensics CTF** where the hash came from a database dump with weak/common passwords — a
  high chance it's already in their wordlist.
- **Identifying the hash type** when you don't know it (the hash length already gives a hint, but
  some services/tools confirm the algorithm).

## When it's NOT worth it / won't work

- **A salted hash with a unique salt** — a lookup is no good; you need `hashcat`/`john` with the
  specific salt (format `hash:salt`).
- **A clearly strong/generated password** (high entropy) — it won't be in any wordlist; the
  challenge's vector is probably not cracking the password but something else (hash reuse, a weak
  comparison, etc.).
- **The hash isn't of a password** (it's of content — e.g. a file hash, HMAC, checksum) — a lookup
  doesn't apply; these databases are of common password/plaintext.

## Online lookup vs. local cracking (hashcat/john)

| Situation | Best approach |
|---|---|
| A common password hash, no visible salt | CrackStation/Hashes.com first — free and instant |
| Not found in the lookup, but it looks like a weak password | Local `hashcat`/`john` with `rockyou.txt` + rules |
| A salted hash (format `hash:salt` given in the challenge) | `hashcat -m <salted_mode>` — online lookup is no good |
| Many hashes at once (a batch/dump) | `hashcat` in batch is more practical than pasting one at a time on the web |
| You need to confirm the hash algorithm | `hash-identifier`/`name-that-hash`, or ask Claude (the length/format is usually enough) |
