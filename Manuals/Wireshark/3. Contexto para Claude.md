# Wireshark / tshark: Context for Claude

Quick competition reference. Prefer **tshark** (CLI) for running via the terminal and piping into
grep/scripts; point the user to the Wireshark GUI when it's visual exploration (Follow Stream,
Export Objects).

## Decision flow (.pcap/.pcapng attachment)

```
1. file + capinfos → confirm it's a capture; if it's a memory dump, it's Volatility, not this
2. tshark -z io,phs → see which protocols exist (defines the target)
3. strings | grep -iE 'flag|pass' → quick win if the flag is in the clear
4. Target protocol in the clear (HTTP/FTP/Telnet/IRC)?
    ├─ yes → Follow Stream / field filters (see table) / Export Objects
    └─ no → is it TLS? is there a key/SSLKEYLOGFILE in the challenge?
        ├─ yes → load the key and re-analyze as clear text
        └─ no → look for an unusual vector: USB HID, DNS/ICMP exfil, pcapng comments
```

## Quick-reference commands

```bash
file chall.pcap && capinfos chall.pcap
tshark -r chall.pcap -q -z io,phs                      # protocols present
tshark -r chall.pcap -q -z conv,tcp                    # conversations
strings -n 6 chall.pcap | grep -iE 'flag|pass|user|token'

# extract fields
tshark -r chall.pcap -Y 'http.request.method=="POST"' -T fields -e http.file_data
tshark -r chall.pcap -Y 'ftp.request' -T fields -e ftp.request.command -e ftp.request.arg
tshark -r chall.pcap -Y 'dns.txt' -T fields -e dns.txt

# follow stream no. N in ascii
tshark -r chall.pcap -q -z follow,tcp,ascii,N

# export transferred files
tshark -r chall.pcap --export-objects http,./out/
```

## Filters that show up most in CTF

| Vector | Filter |
|---|---|
| HTTP login/upload | `http.request.method == "POST"` |
| FTP credential | `ftp.request.command in {"USER","PASS"}` |
| DNS exfil | `dns.txt` / `dns.qry.name` |
| USB keyboard | `usb.capdata` (translate HID keycodes) |
| Clear text | `telnet` / `irc` / `data-text-lines` |
| ICMP with payload | `icmp && data.len > 0` |

## TCP stream reassembly and overlapping segments

When a stream is split across many segments, the dissector stitches them back together. Two traps
show up in CTF: reassembly turned off, and segments that overlap at the same sequence number with
different bytes (one is the decoy, one is the real payload).

```bash
# force TCP reassembly on (so the upper-layer payload is rebuilt from the segments)
tshark -r chall.pcap -o tcp.desegment_tcp_streams:TRUE -Y http -T fields -e http.file_data

# spot the anomalies that signal a hand-crafted overlap
tshark -r chall.pcap -Y 'tcp.analysis.retransmission || tcp.analysis.out_of_order'
tshark -r chall.pcap -Y 'tcp.analysis.flags'            # includes the overlap/conflict expert info

# dump each segment's payload next to its seq/len so you can compare bytes at the SAME seq
tshark -r chall.pcap -Y 'tcp.port==PORT' -T fields -e tcp.seq -e tcp.len -e data
```

Why Follow Stream can hide the answer: the reassembler keeps **one** copy per byte offset, so when
two segments claim the same seq with different data, Follow Stream (and `--export-objects`) shows
only the copy it picked and silently drops the conflicting one. Compare the raw per-segment `data`
at the duplicated seq to recover both the decoy and the real bytes. See
`Arsenal/FOR/tcp-overlapping-segment-conflict.md` for the full pattern.

## Gotchas to remember in the moment

- **TLS with no key won't decrypt**: don't push it; find the key in the attachments or switch
  vectors.
- `Content-Encoding: gzip` → Export Objects decompresses; by hand, `gunzip`.
- A flag **sliced** across packets/subdomains → concatenate before decoding (base32/base64/hex).
- USB HID requires a **scancode map** (it's not direct ASCII): reconstruct with a keycode table.
