# ffuf: Context for Claude

Quick competition reference. ffuf runs from the terminal. The role here is to place the `FUZZ`
keyword in the right spot, pick a wordlist, and filter the response noise so the real hits surface.

## Decision flow (web target, vector unknown)

```
What do you want to fuzz?
 ├─ a path / file        → -u http://host/FUZZ      (+ -e for extensions, -recursion to go deeper)
 ├─ a virtual host       → -u http://host/ -H "Host: FUZZ.target.ctf"
 ├─ a parameter name     → -u 'http://host/p?FUZZ=test'   (or -d 'FUZZ=test' for POST)
 └─ a parameter value    → -u 'http://host/p?id=FUZZ'
Then: is every response the same (soft-404)?
 ├─ yes → -ac, or -fs/-fw/-fl on the baseline, or -fc 404 -mc 200,301,302,403
 └─ no  → read the hits; getting 429/403 walls → lower -rate and -t
```

## Quick-reference commands

```bash
# directory + file brute force with extensions and recursion
ffuf -w /usr/share/seclists/Discovery/Web-Content/common.txt -u http://host/FUZZ \
     -e .php,.txt,.bak -recursion -recursion-depth 2

# soft-404 handling
ffuf -w common.txt -u http://host/FUZZ -ac              # auto-calibrate
ffuf -w common.txt -u http://host/FUZZ -fs 1234         # filter by size
ffuf -w common.txt -u http://host/FUZZ -fc 404 -mc 200,301,302,403

# vhost / subdomain
ffuf -w subdomains-top1million-5000.txt -u http://host/ -H "Host: FUZZ.target.ctf" -fs 0

# parameter name (GET) and value, POST body
ffuf -w burp-parameter-names.txt -u 'http://host/page?FUZZ=test' -fs 4242
ffuf -w params.txt -u http://host/login -X POST \
     -H "Content-Type: application/x-www-form-urlencoded" -d 'FUZZ=test' -fs 4242

# headers / cookies / auth, and a raw request from Burp
ffuf -w list.txt -u http://host/FUZZ -H "Cookie: session=abc"
ffuf -request req.txt -request-proto http -w list.txt

# rate / threads
ffuf -w list.txt -u http://host/FUZZ -t 40 -rate 50
```

## Common failure modes (and the cause)

| Symptom | Likely cause |
|---|---|
| Every word returns `200`, thousands of "hits" | Soft-404 page: add `-ac` or filter the baseline with `-fs`/`-fw` |
| ffuf exits instantly, does nothing | No `FUZZ` keyword anywhere in URL/header/body |
| Results become a wall of `429`/`403` | Target is rate-limiting: drop `-rate` and `-t` |
| Nothing found at all | Wrong wordlist, or missing `-e` extensions, or the vector is not path-based |
| Real pages filtered away with the noise | `-fs` baseline was too broad: switch to `-fw`/`-fl` or `-ac` |
| Vhost fuzz returns the default site for every word | Filter the default vhost size (`-fs <that size>`) so only real vhosts show |

## When to flag that fuzzing is not the vector

- The prompt already points at a concrete bug (SQLi, JWT, LFI, SSRF): fuzzing paths burns time.
- After a medium wordlist and `-ac` turns up nothing interesting, stop: the flag is behind logic,
  not a hidden path.
