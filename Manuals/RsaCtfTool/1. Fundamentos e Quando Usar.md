# RsaCtfTool — Fundamentals and When to Use It

Manual for `RsaCtfTool`, the automator for attacks against weak CTF RSA. Walkthrough in
`2. Guia Passo a Passo.md`; competition reference in `3. Contexto para Claude.md`.

## What it is

`RsaCtfTool` (https://github.com/RsaCtfTool/RsaCtfTool) tries, in sequence, dozens of known
attacks against poorly generated RSA keys. You give it what you have (a public key `.pem`, or
`n`/`e`, and optionally the ciphertext) and it sweeps the applicable attacks until it recovers the
private key or decrypts the message.

## What it tries (covered attacks)

- **Small / factorable `n`** — direct factorization (queries FactorDB, trial division).
- **Fermat** — `p` and `q` very close.
- **Small `e` (`e=3`)** — root attack when `m^e < n` (no padding).
- **Wiener / Boneh-Durfee** — small `d` (short private exponent).
- **Common modulus** — same `n`, two different `e`.
- **Håstad broadcast** — same `m` encrypted with a small `e` for several `n`.
- **Partial key / known primes**, keys with bad entropy, and several others.

## Key concept: identify the attack from the parameters

Before running everything blindly, look at the numbers (see `Arsenal/CRYPTO/`): a huge `e` → likely
Wiener; two files with the same `n` → common modulus; `e=3` + ciphertext → root attack. This avoids
waiting for the full sweep.

## When it's worth using

- **CRYPTO** with RSA where the key/params look weak: small `n`, a strange `e` (3 or enormous),
  multiple related keys, a `.pem` given to break.
- When you recognize the pattern but don't want to reimplement the attack by hand — the tool
  already has it.

## When it's NOT worth it

- **Well-done RSA** (a 2048+ bit n, `e=65537`, OAEP padding) — it won't break; the challenge's
  vector is something else (key leak, padding oracle, signature, nonce reuse).
- **Trivial math by hand** (e.g. an `n` you factor in your head, `e=1`) — solving it directly is
  faster (solving by hand is often faster than an AI round-trip).
- It's not RSA (it's ECC, AES, a classical cipher) — wrong tool.

## Tools that go with it

- **FactorDB** (http://factordb.com) — check whether `n` is already factored (RsaCtfTool uses it,
  but it's worth checking by hand).
- **SageMath / Python (`pycryptodome`, `gmpy2`, `sympy`)** — for attacks the tool doesn't cover or
  for building the final decrypt from `p`,`q`.
- **openssl** — inspect/convert `.pem` keys (`openssl rsa -pubin -text -in key.pem`).
