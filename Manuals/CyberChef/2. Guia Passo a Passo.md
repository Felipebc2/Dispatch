# CyberChef: Step-by-Step Guide

Practical workflow, from zero to decoding/solving a blob of data. Concepts and "when to use" are
in `1. Fundamentos e Quando Usar.md`.

## 0. Open and prepare

1. Go to https://gchq.github.io/CyberChef/ (leave a tab open ahead of the event; it works
   offline once loaded a single time, so it doesn't depend on internet access during the
   competition).
2. The interface has 4 columns: **Operations** (left) → **Recipe** (center-left) → **Input**
   (center-right, paste the challenge data here) → **Output** (right, the result).

## 1. Simple case: you already know the encoding

1. Paste the data into **Input**.
2. Find the operation in the search box above **Operations** (e.g. "From Base64").
3. Drag it (or double-click) to drop it into the **Recipe**.
4. The **Output** updates on its own (Auto Bake is on by default). If it's off, click **Bake**.
5. Chain more operations as needed (e.g. `From Base64` → `From Hex`); the output of one becomes
   the input of the next automatically.

## 2. The "I don't know what this is" case

1. Paste the data into **Input**.
2. Find the **Magic** operation and drag it into the **Recipe**.
3. CyberChef tests several combinations and suggests the most likely recipes, ordered by
   "score". Click whichever suggestion makes sense to apply it automatically.
4. If Magic doesn't find anything good, eyeball the Input: `==` at the end suggests Base64,
   only `0-9a-f` suggests hex, `%XX` suggests URL-encode, etc.

## 3. Most common operations in CTF

| What you want | Operation (search by name) |
|---|---|
| Decode Base64/Base32/Base58 | `From Base64`, `From Base32`, etc. |
| Hex ↔ text | `From Hex` / `To Hex` |
| XOR with a known key | `XOR` (give the key in Hex/UTF8/Base64) |
| XOR with an unknown key (partial known plaintext) | `XOR Brute Force` |
| Caesar/ROT | `ROT13` (adjustable to other shifts) |
| Vigenère | `Vigenère Decode` (with a key) or `Vigenère Brute Force` |
| Hash (compute, not crack) | `MD5`, `SHA1`, `SHA2`, etc. (the Hashing category) |
| Extract IPs/URLs/emails from a blob | `Extract IP addresses`, `Extract URLs`, `Extract Email Addresses` |
| Compress/decompress | `Gunzip`, `Raw Inflate`, `Zlib Inflate`, etc. |
| JWT (decode, inspect claims) | `JWT Decode` (but to attack the secret, see the JWT manual) |
| AES/DES (with known key/IV) | `AES Decrypt` / `DES Decrypt` (the Encryption category) |

## 4. Saving/sharing a recipe

- **URL:** CyberChef updates the browser URL as you build the recipe, so copying that URL recreates
  the recipe (and optionally the input) for whoever opens it later. Useful for saving a recipe
  that worked, or for asking for help by showing exactly what you tried.
- **Save/Load recipe:** the disk icon at the top of the Recipe column, which saves as a local `.json`
  file.

## 5. Practical routine (unknown data blob)

1. Paste into Input, drop `Magic` into the Recipe first.
2. If that doesn't solve it: look at the format visually (characters, padding, length) and guess
   the first layer manually (`From Base64`, `From Hex`, etc.).
3. Repeat, chaining one operation per layer, until the Output turns into readable text or the
   flag.
4. If you get stuck on a specific layer (e.g. "looks binary but won't decode"), consider that it
   may no longer be an encoding problem but something in another category (e.g. forensics, where it's an
   embedded file; use CyberChef's `Detect File Type` or `File Signature Extractor` to confirm).
