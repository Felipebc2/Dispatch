# Windows-Registry: Context for Claude

Quick competition reference for offline hive forensics. The role here is to pick the right hive and
artifact for the question, replay logs first, then read the value and cross-check it.

## Decision flow

```
What does the question want?
 ├─ "what program ran / was seen" → ShimCache (SYSTEM), Amcache.hve, BAM (SYSTEM), UserAssist (NTUSER)
 ├─ "what persisted / autostarts"  → Run/RunOnce (SOFTWARE), Services (SYSTEM)
 ├─ "what did the user open/browse"→ RecentDocs, TypedPaths, ShellBags (NTUSER.DAT)
 ├─ "local accounts / hashes"      → SAM (+ SYSTEM for the bootkey)
 └─ always: replay .LOG1/.LOG2 before parsing; pick the Current ControlSet
```

## Quick-reference commands

```bash
registry-transaction-logs SYSTEM --log SYSTEM.LOG1 --log SYSTEM.LOG2 -o SYSTEM.clean  # step 0
regipy-dump SYSTEM -p '\Select'                 # which ControlSet is Current
regipy-dump SYSTEM -p shimcache                 # AppCompatCache (path + file-modified FILETIME)
regipy-dump SYSTEM -p bam                        # BAM/DAM last run time
regipy-dump SOFTWARE -p '\Microsoft\Windows\CurrentVersion\Run'   # autostart
regipy-dump NTUSER.DAT -p userassist             # GUI launches (names ROT13)
AppCompatCacheParser.exe -f SYSTEM --csv . --csvf shim.csv
AmcacheParser.exe -f Amcache.hve --csv . --csvf amc.csv
rip.pl -f system -p appcompatcache               # RegRipper alternative
```

## Common failure modes (and the cause)

| Symptom | Likely cause |
|---|---|
| Values look stale or a key is missing | dirty hive; replay `.LOG1`/`.LOG2` first |
| Parsing the wrong settings | used the wrong ControlSet; read `\Select` -> Current = N |
| ShimCache time does not match "when it ran" | it is the file last-modified time, not an execution time |
| UserAssist program names are gibberish | they are ROT13 encoded; decode them |
| Amcache not found in SYSTEM | Amcache is its own hive (`Amcache.hve`), not inside SYSTEM |
| A path entry looks planted | cross-check against Amcache SHA1 or the on-disk binary |

## When to flag that registry is not the vector

- The evidence lives in `.evtx` event logs or a memory dump: wrong tool, use an evtx parser or
  Volatility.
- The question is really "recover this file": carve it from the disk image instead.
