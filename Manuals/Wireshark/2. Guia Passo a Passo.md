# Wireshark / tshark: Step-by-Step Guide

Workflow for analyzing a CTF `.pcap`, from the overview to extracting the flag. Concepts are in
`1. Fundamentos e Quando Usar.md`.

## 0. Confirm the file and get an overview

```bash
file chall.pcap                              # confirm it's a capture (pcap/pcapng)
capinfos chall.pcap                          # number of packets, time range, size
tshark -r chall.pcap -q -z io,phs            # protocol hierarchy: where to focus
tshark -r chall.pcap -q -z conv,tcp          # TCP conversations (source/dest/ports)
```
The protocol hierarchy tells you the target: is there HTTP? FTP? DNS with lots of TXT? USB traffic?

## 1. Quick sweep for a flag/secret

```bash
strings -n 6 chall.pcap | grep -iE 'flag|user|pass|pwd|token|secret'
```
If the flag is in the clear in a payload, this already solves it.

## 2. Most useful display filters

| Goal | Filter (GUI and `tshark -Y`) |
|---|---|
| HTTP requests only | `http.request` |
| POSTs (login/upload) | `http.request.method == "POST"` |
| FTP credentials | `ftp.request.command == "USER" || ftp.request.command == "PASS"` |
| A specific host | `ip.addr == 10.0.0.5` |
| A port/service | `tcp.port == 1337` |
| DNS (common exfil over TXT) | `dns` / `dns.txt` |
| Telnet/IRC in the clear | `telnet` / `irc` |

Extract fields on the CLI:
```bash
tshark -r chall.pcap -Y 'http.request.method=="POST"' -T fields -e http.file_data
tshark -r chall.pcap -Y 'ftp.request' -T fields -e ftp.request.command -e ftp.request.arg
tshark -r chall.pcap -Y 'dns.txt' -T fields -e dns.txt
```

## 3. Follow streams (reconstruct a session)

- **Wireshark GUI:** click a packet from the conversation → `Follow` → `TCP Stream` (or HTTP/UDP).
  Shows the entire dialog in the clear; switch the view to "raw"/"hex" if it's binary.
- **CLI equivalent** (stream no. 3, for example):
```bash
tshark -r chall.pcap -q -z follow,tcp,ascii,3
```

## 4. Export transferred files

```bash
mkdir out
tshark -r chall.pcap --export-objects http,./out/     # all HTTP objects
# GUI: File > Export Objects > HTTP / SMB / TFTP / IMF
file out/* ; strings out/* | grep -iE 'flag'          # analyze what came out
binwalk out/<file>                                    # if it's an image/binary with something embedded
```

## 5. Special cases common in CTF

- **TLS with a provided key:** `Edit > Preferences > Protocols > TLS > (Pre)-Master-Secret log
  filename` pointing at the challenge's `SSLKEYLOGFILE`; then the HTTPS becomes readable HTTP.
- **USB (HID keyboard):** `usb.capdata` captures carry typed keystrokes. Map the HID keycodes to
  reconstruct what was typed (a scancode-translation script).
- **DNS exfiltration:** data sliced across subdomains/TXT. Concatenate the fields and decode
  (often base32/hex).
- **ICMP / unusual fields:** a flag hidden in the `data` of ICMP packets or in pcapng comments.
- **Overlapping TCP segments:** retransmissions that carry *different* bytes at the same `tcp.seq`.
  Follow Stream shows only the copy the reassembler kept; dump `-T fields -e tcp.seq -e tcp.len -e
  data` to compare both. See file 3 and `Arsenal/FOR/tcp-overlapping-segment-conflict.md`.
