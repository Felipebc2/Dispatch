# Ghidra — Context for Claude

Quick reference to consult without rereading the full manuals
(`1. Fundamentos e Quando Usar.md`, `2. Guia Passo a Passo.md`). Format: facts, commands,
heuristics — not a didactic explanation.

## Summary in 3 lines

Ghidra decompiles binaries (ELF/PE/etc.) into pseudo-C. GhidraMCP exposes 253 MCP tools to operate
Ghidra through conversation instead of clicking: list functions, decompile, rename, xref, structs,
P-code emulation. Already registered as the `ghidra` MCP server, in a local scope, active only in
sessions opened inside the directory where the server is registered.

## Session prerequisite

- **Ghidra must be open** with a binary loaded for the MCP to respond usefully.
- Quick check: `curl http://127.0.0.1:8089/check_connection`
  - `"but no program loaded"` → Ghidra is open, the binary still needs to be imported/opened (see the Guide, steps 1-3)
  - `Connection refused` → Ghidra isn't running, open it with `/opt/ghidra/ghidraRun`
- If the MCP doesn't respond even with Ghidra open: confirm the Claude Code session was opened
  inside the directory where the server is registered (the server's local scope).

## Map: request → MCP tool

| User request | Tool(s) |
|---|---|
| List the binary's functions | `list_functions`, `list_functions_enhanced` |
| Find suspicious strings (`"flag{"`, "Wrong", "Correct") | `search_strings`, `list_strings` |
| Decompile and explain a function | `decompile_function` |
| Who calls / is called by a function | `get_function_callers` / `get_function_callees` |
| Rename a function | `rename_function` |
| Rename/type variables in bulk | `rename_variables`, `set_variables` |
| Comment a function/line | `set_comment` (Plate/EOL) |
| View a struct's layout | `get_struct_layout` |
| Where an address/string is referenced | `get_xrefs_to` / `get_xrefs_from` |
| Dataflow analysis / P-code emulation | `analyze_dataflow`, emulation tools |
| Full call graph | `get_full_call_graph`, `analyze_call_graph` |
| Compare two versions of the same binary (patch diff) | `diff_functions`, `find_similar_functions*` |
| Search for a byte / instruction pattern | `search_byte_patterns`, `search_instructions` |

The full list of available tools is in `list_tool_groups` / `search_tools` if you need something
outside this table.

## Recommended flow for a CTF binary (REV)

1. `list_functions_enhanced` → map the binary (size, how many functions, names already readable)
2. `search_strings` → look for validation strings (`"flag{"`, `"Wrong"`, `"Correct"`, and the
   CTF's configured flag format)
3. `get_xrefs_to` on the string you found → the function that uses it
4. `decompile_function` on that function → read the validation logic
5. `get_function_callers` to climb the chain if the real logic is elsewhere
6. Reconstruct the condition (`strcmp`, byte-by-byte loop, XOR, etc.) — sometimes you can invert it
   directly by reading the pseudo-C, sometimes you need to run/emulate
7. `rename_function` / `rename_variables` as you understand, to keep the code readable if the
   challenge has multiple stages

## Signs the challenge is Pwn/Binary (not pure REV)

- Ghidra still helps (understanding the vulnerable function, viewing protections), but the goal is
  to write an exploit, not just read. Check protections first: `checksec` (outside Ghidra, via the
  shell) — canary, NX, PIE, RELRO.
- Look for `gets`, `strcpy`, `sprintf`, `system`, `read` without a bound check via `search_strings`
  / import xrefs.

## Limitations and caveats

- Decompilation **is not the real source code** — variables/types are inferred and may be wrong;
  cross-check against the Listing (assembly) if something doesn't add up.
- Binaries with a **packer/obfuscation** (UPX, custom) may require manual unpacking before Ghidra
  can really analyze them — signs: few functions detected, high entropy, a tiny `.text` section.
- P-code emulation is useful for running an isolated snippet, but it doesn't replace actually
  running the binary when you can (faster to confirm a hypothesis by executing).
- Bulk renaming/commenting is great for large binaries, but avoid asking for it on small/obvious
  challenges — in the time it takes to describe the request you'd already have read the function
  yourself.

## When NOT to use Ghidra (or the MCP)

See the "When it's NOT worth it" section of `1. Fundamentos e Quando Usar.md`: trivial encoding
(CyberChef handles it), pure crypto with no binary, or when you already recognize the pattern off
the top of your head.
