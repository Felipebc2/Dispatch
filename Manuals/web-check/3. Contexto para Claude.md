# Web Check: Context for Claude

Quick competition reference. Web Check (by Alicia Sykes, https://github.com/lissy93/web-check) runs
in the user's browser at `https://web-check.xyz/check/<target>`; you work with its exported JSON.

## Rules

- **Never `cat`/Read the raw `web-check-results.json`.** It can be 700+ KB (~180k tokens), almost
  all of it Lighthouse (`quality`) and a base64 `screenshot`. Always filter with `jq` first.
- **Don't call `web-check.xyz/api/*`.** It answers scripts with a 429 checkpoint page. If there is no
  JSON yet, give the user the `https://web-check.xyz/check/<target>` link and ask for the export, or
  just do the recon directly (`generic-recon-scanner`).
- Private/VPN/offline target: skip Web Check, recon with `curl`/`dig`/`ffuf`.

## Filters (pick the smallest that answers the question)

```bash
F=web-check-results.json
jq -r 'keys | join(", ")' "$F"                                        # what's in it
jq -c '{"robots-txt", sitemap, "linked-pages"}' "$F"                  # paths to visit
jq -c '{dns, "txt-records", ssl: .ssl.subjectaltname}' "$F"          # DNS/TXT + cert hostnames
jq -c '{headers, cookies, redirects, "tech-stack"}' "$F"              # app fingerprint
jq -c 'del(.quality, .screenshot)' "$F"                               # everything useful (~12 KB)
jq -r 'to_entries[] | select((.value|type)=="object" and (.value.error or .value.skipped)) | .key' "$F"
```

## Decision flow

```
Have a web/domain target?
 ├─ public, user has (or can make) a Web Check JSON → filter it, list leads, confirm with curl/dig
 ├─ public, no JSON                                 → give the /check/<target> link, or recon directly
 └─ private / VPN / offline                         → generic-recon-scanner (curl, ffuf), no Web Check
Lead found?
 ├─ path (robots/sitemap/links) → curl it
 ├─ TXT / hostname              → dig it, domain-recon-certificates-dns
 └─ version / JWT / cookie      → --toolset net/vuln-db, Arsenal/WEB entries
```
