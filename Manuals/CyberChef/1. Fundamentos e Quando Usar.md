# CyberChef — Fundamentals and When to Use It

Introductory manual: what CyberChef is, the core concepts (Recipe/Bake), and when it's worth
using in a CTF. The practical walkthrough is in `2. Guia Passo a Passo.md`.

## What CyberChef is

CyberChef is "the Swiss Army knife" of encoding/decoding/crypto — a web tool (runs 100% in the
browser, without sending data to any server) built by GCHQ (the British intelligence service) to
transform data in a chain: decode, encrypt/decrypt, extract, convert formats.

Access: https://gchq.github.io/CyberChef/ (official standalone version; works offline once loaded
a single time — worth saving locally/bookmarking ahead of the event so you don't depend on
internet access during the competition).

## Key concepts

- **Recipe:** a sequence of chained operations. The output of one operation becomes the input of
  the next. E.g. `From Base64 → From Hex → XOR`.
- **Operations:** transformation blocks (categories: Data Format, Encryption/Encoding,
  Extractors, Compression, etc.). Drag them from the left-hand list to build the recipe.
- **Bake:** the button that runs the recipe over the Input and shows the Output. "Auto Bake" mode
  runs on every change.
- **Magic wand (the "Magic" operation):** tries to automatically detect which encoding/transform
  is in use and suggests a recipe. A great starting point when you don't know what you're
  looking at.
- **Recipe URL:** CyberChef encodes the whole recipe (plus the input, optionally) in the URL — you
  can share or save a prepared recipe as a link.

## When it's worth using

- **Layered encodings:** base64 inside hex inside URL-encode, etc. — build the chain visually
  instead of decoding one layer at a time by hand/CLI.
- **You can't identify the encoding:** throw it at the Magic wand for a quick guess.
- **Simple/classical crypto:** XOR (with or without key brute-force), Caesar/ROT, Vigenère,
  custom Base-N.
- **Extracting data from a blob:** pull IPs, URLs, emails, or hashes out of a large chunk of text
  (the Extractors category).
- **Quick conversions:** hex↔ASCII, decimal↔binary, date formats, etc.

## When it's NOT worth it

- **A single, obvious operation** (e.g. just one base64) — faster in the terminal: `base64 -d`,
  `echo ... | xxd -r -p`, or even in the Python REPL.
- **Heavy crypto with an unknown key and a large keyspace** (broken RSA, AES with brute-force over
  millions of keys) — CyberChef isn't performant for this; use dedicated tools
  (`RsaCtfTool`, `hashcat`, Python scripts with `pycryptodome`).
- **You need scripting/conditional logic** — CyberChef is a linear pipeline; if the logic requires
  "if X then Y", it's faster to write a script.

## CyberChef on its own vs. asking Claude

| Situation | Best approach |
|---|---|
| You already know the encoding chain | CyberChef directly — visual, fast, no commands to type |
| You can't identify the encoding | Magic wand in CyberChef, or ask Claude "what encoding is this?" |
| You need to repeat the same recipe across many inputs (batch) | Claude/script — CyberChef is manual, one input at a time in the UI |
| A long chain where you want to confirm each step | CyberChef — it shows the intermediate output of every operation |
| XOR brute-force against a known plaintext | CyberChef's `XOR Brute Force` operation, or let Claude generate a script if the search space is large |
