# WebAssembly: Context for Claude

Quick competition reference for a `.wasm` module. The role here is to pick between reading the
lifted code and driving the exports, then recover or forge whatever the module checks.

## Decision flow

```
Have a .wasm (or a page that instantiates one)?
 ├─ exports look like a checker/keygen (check/validate/main)?
 │   ├─ yes → drive it: node instantiate + call the export with candidate input (fastest)
 │   └─ no  → read it: wasm-decompile for logic, wasm2wat for exact opcodes
 ├─ need a constant/expected bytes/key? → wasm-objdump -s -j data (note the memory offset)
 └─ logic seems missing? → it is in the JS glue (Emscripten); read the .js, not just the wasm
```

## Quick-reference commands

```bash
wasm-objdump -x mod.wasm                 # sections, imports, exports, memory, data table
wasm2wat mod.wasm -o mod.wat             # readable text format (1:1 opcodes)
wasm-decompile mod.wasm -o mod.dcmp      # C-like view for control flow
wasm-objdump -s -j data mod.wasm         # raw data section bytes + offsets
wasm-validate mod.wasm                   # well formed?
wasm2c mod.wasm -o mod.c                 # lift to C to instrument/print
```

```js
// node: load and call an export (stub imports as needed)
const { instance } = await WebAssembly.instantiate(require('fs').readFileSync('mod.wasm'), { env: {} });
const mem = new Uint8Array(instance.exports.memory.buffer);
```

## Common failure modes (and the cause)

| Symptom | Likely cause |
|---|---|
| `WebAssembly.instantiate` throws on load | an import is missing; stub every `env`/`wasi` import the objdump lists |
| The checker always returns the same value | a start function mutated memory before your call; re-init per call |
| Bytes at your offset look wrong | memarg `offset` adds to the address; the real offset is base plus the immediate |
| A 2-value branch picks the wrong side | `select` pops `cond` last; operand order is `a b cond` |
| A size field is off | LEB128 is variable length; a value can be 1 to 5 bytes, not fixed width |
| No logic in the module | it is Emscripten glue; the check is in the JavaScript |

## When to flag that wasm is not the vector

- The module only exports `memory` and allocator helpers: the logic is in the JS host.
- The interesting comparison is against a value fetched over the network: it is a web/API problem,
  not static wasm reversing.
