# ffuf: Step by Step

Practical workflow for fuzzing a web target with ffuf, from a directory sweep to parameter mining.
Concepts in `1. Fundamentos e Quando Usar.md`.

## 0. Install and wordlists

```bash
# Arch:
sudo pacman -S --needed ffuf seclists
# wordlists then live under /usr/share/seclists/
```
Wordlists used most in CTF (SecLists paths):
- Directories: `/usr/share/seclists/Discovery/Web-Content/common.txt` (small, fast first pass),
  `.../directory-list-2.3-medium.txt` (big second pass).
- Files/backups: `.../Discovery/Web-Content/raft-medium-files.txt`.
- Vhosts/subdomains: `/usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt`.
- Parameters: `/usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt`.

## 1. Directory and file brute force

```bash
ffuf -w /usr/share/seclists/Discovery/Web-Content/common.txt -u http://host/FUZZ
```
Add extensions so each word is tried with each suffix (`admin` plus `admin.php`, `admin.bak`, ...):
```bash
ffuf -w common.txt -u http://host/FUZZ -e .php,.txt,.bak,.html
```
Recurse into every directory ffuf finds, up to a depth:
```bash
ffuf -w common.txt -u http://host/FUZZ -recursion -recursion-depth 2
```

## 2. Beat the soft-404 (filtering)

If every path returns `200` with the same body, filter it. First look at the baseline size, then
drop it, or let auto-calibration do it:
```bash
ffuf -w common.txt -u http://host/FUZZ -fs 1234          # drop responses of exactly 1234 bytes
ffuf -w common.txt -u http://host/FUZZ -ac               # auto-calibrate the "not found" baseline
ffuf -w common.txt -u http://host/FUZZ -fc 404 -mc 200,301,302,403   # explicit status match/filter
```
`-fw` (word count) and `-fl` (line count) are the fallbacks when the size varies slightly per page.

## 3. Virtual-host and subdomain fuzzing

Same IP, many sites selected by the `Host` header. Keep the URL fixed and fuzz the header:
```bash
ffuf -w subdomains-top1million-5000.txt \
     -u http://host/ -H "Host: FUZZ.target.ctf" \
     -fs 0                         # or filter the default vhost's size once you know it
```

## 4. Parameter and value fuzzing

Find a hidden GET parameter name:
```bash
ffuf -w burp-parameter-names.txt -u 'http://host/page?FUZZ=test' -fs 4242
```
Fuzz a POST body (note `-d` and the content-type header):
```bash
ffuf -w params.txt -u http://host/login \
     -X POST -H "Content-Type: application/x-www-form-urlencoded" \
     -d 'FUZZ=test' -fs 4242
```
Guess a value for a known parameter (e.g. a numeric id or PIN):
```bash
ffuf -w /usr/share/seclists/Fuzzing/4-digits-0000-9999.txt \
     -u 'http://host/reset?pin=FUZZ' -fc 403
```

## 5. Headers, cookies, auth, and raw requests

```bash
ffuf -w list.txt -u http://host/FUZZ -H "Cookie: session=abc" -H "Authorization: Basic ..."
```
Save a request from Burp to a file (keep the literal `FUZZ` where you want it) and replay it:
```bash
ffuf -request req.txt -request-proto http -w list.txt
```

## 6. Rate and threads

```bash
ffuf -w list.txt -u http://host/FUZZ -t 40          # 40 concurrent threads (default)
ffuf -w list.txt -u http://host/FUZZ -rate 50       # cap at 50 requests/second
ffuf -w list.txt -u http://host/FUZZ -t 5 -rate 20  # back off when the target rate-limits
```
If results suddenly turn into a wall of `429`/`403`, lower `-rate` and `-t`; a throttled target
returns garbage, not findings.
